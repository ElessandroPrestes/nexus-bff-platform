# Boas Práticas

## Especificação

- Escreva critérios de aceite testáveis.
- Declare não-objetivos para conter escopo.
- Registre perguntas abertas em vez de supor.

## Implementação

- Menor mudança possível para satisfazer a SPEC.
- Sem dependências novas sem justificativa.
- Sem refatorações amplas não solicitadas.
- Sem segredos no código ou no repositório.

## Testes

- Cubra critérios de aceite.
- Registre evidências rastreáveis.
- Automatize o que for repetível.

## Revisão

- Revise contra a SPEC, não contra preferências pessoais.
- Separe design review de code review quando houver interface.

## Documentação

- Atualize junto com o código.
- Mantenha `PROJECT.md` como fonte de verdade.
